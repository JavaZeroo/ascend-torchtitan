Architecture Review · L0 compat / L1 kernels

shim 与 override 机制架构审查

对 ascend_titan.compat（受治理 monkeypatch）与 torchtitan @override（配置期节点替换）两条接缝的整体审视——设计是否合理、是否存在可优化点，以及目标形态。

0 · 结论 verdict

设计是合理且克制的：两条接缝分工清晰、各自有治理 teeth，且没有重写上游机制（P10 / P6）。 主要问题不是机制本身，而是三处表达层的债——(1) 兄弟 override 靠 recipe 里的 list 手术来规避节点冲突、语义不可见； (2) 融合 GDN 的 inner-net 逐字重复了纯 torch 版 forward（DRY 破坏）；(3) 两张文档表与代码不同步。 这些都不影响当前正确性，但会让下一个加 override / shim 的人踩进同一个坑。建议按 §3 的优先级收敛。

1 · 现状架构 current

两条接缝都在 _bootstrap.setup() 之后、模型 build 之前生效：shim 治"import 期 / 自由函数写死 CUDA、又没有配置开关、override 够不着"的代码（L0）；override 治"存在 Configurable.Config 节点"的可替换计算（L1）。分界线是 P6。

2 · 设计合理性 assessment

合理接缝边界清晰

  • override 优先、shim 兜底：能触及 Configurable.Config 就走 override（P6），只有自由函数/import 期写死才用 shim（ADR-002）。这条分界避免了"能用 override 却退化成 monkeypatch"的慢性腐烂。
  • 没有 fork 上游机制：override 是 torchtitan 自带能力，我们只作为消费方注册工厂；shim 只是补上游没有扩展点的缺口（P10）。

合理治理有 teeth

  • shim：import 时强制 reason/upstream，replace 必须写 why_not_wrap（P3/P4）；polyfill 在上游补 API 后自动 no-op。
  • override：继承上游 per-node 冲突检测 + derive() + fqns/exact，版本漂移风险被 derive 吸收。
  • 依赖分层：基础依赖硬导入（P14/ADR-007），可选加速包走 optional_module + WARNING（ADR-004），torch_npu 缺陷绝不绕（P1/P9）。

3 · 优化清单 ranked

按影响排序。①②③ 建议尽快，④⑤⑥ 属于打磨。

级问题建议影响
① 高 兄弟 override 用 list 手术规避节点冲突：gdn.py 与 gdn_fla.py 同 target InnerGatedDeltaNet.Config，靠 [imp for imp in ... if imp != GDN_OVERRIDE] 换掉。语义藏在 recipe 里，审计不可见、易漏。 把 swap 收敛成 transforms.py 的一个显式助手（或数据表驱动），recipe 与 transform 共用，并写清"同一节点、互斥"语义。 审计可见、新增第三个 sibling 不再重蹈覆辙。
② 高 融合 inner-net 重复实现：AscendFusedInnerGatedDeltaNet(InnerGatedDeltaNet) 逐字复制 AscendInnerGatedDeltaNet.forward（conv + gate 数学 ~48 行）。 改为继承 AscendInnerGatedDeltaNet，只替换 kernel 配置为 AscendFusedGatedDeltaKernel.Config；forward 保持不变。 DRY + 单一事实来源；上游 conv/gate 改动自动继承。
③ 中 文档与代码不同步：kernels/__init__.py 仍写 "Nothing lives here yet (M3)"；kernels/README.md 表格缺 gdn.py/gdn_fla.py/kda.py 三行。 更正 __init__ docstring；补全 README 表格行（含每文件的 target 节点与依赖层级）。 P11 单一事实来源，避免"文档里的机制 ≠ 代码里的机制"。
④ 中 "import 无副作用"表述不准：kernels/__init__.py 要求模块 import 无副作用，但 situ_glu.py/gdn_fla.py 都在 import 时打 WARNING（ADR-004 许可的响亮降级）。 把措辞改为"import 时不得触发 NPU 算子加载；可选包探测 + WARNING 是唯一允许的 import 期副作用"。 消除自相矛盾的契约，防止有人把 WARNING 当违规删掉。
⑤ 低 shim 无显式 apply 顺序：dict 插入序隐式决定；现有 3 条 shim 无依赖所以没事，但 wrap 叠加是脆的。 在 doctor 输出 shim 清单 + apply 顺序；若无依赖则显式声明"无顺序依赖"。 为未来 shim 增长留一个可诊断的护栏。
⑥ 低 override 无静态审计表：冲突只靠运行时 _check_node_conflicts 兜底，写 recipe 时不可见。 引一张纯数据表（同 registry.py/triage.toml 风格）：override 工厂 → 目标节点 → kind(minimal/fused) → golden → 依赖包，供 doctor/provenance 消费。 把"哪些 override 活跃、claim 了谁、是否互斥"从隐式逻辑变成显式数据（P11）。
